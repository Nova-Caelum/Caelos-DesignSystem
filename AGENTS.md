# Caelos design system — first principles

- Every user action must provide visual feedback. The visible result itself can supply that feedback: an opened menu, dialog, or destination page does not need a separate Success treatment.
- Pressed acknowledges activation immediately. Reserve Success for an operation that actually completed and needs explicit confirmation, such as a save, a sent message, or a script generated in the background. If the result is immediately visible, use that result as feedback; Success is not required. A click or elapsed timer never proves success.
- Hover and keyboard focus share an appearance while retaining separate interaction behavior. For the primary button, use `controls.shared.button.$extensions["app.caelos"].statePaints.primary` in `token_catalog/02-controls.tokens.json`; its Hover and Focus entries select the same shared appearance, whose ingredients reference the lower-tier blue foreground and soft surface-edge glow. Keep Pressed visibly distinct while a pointer or keyboard activation is held, then restore the appropriate interaction state on release. Preserve keyboard operation and visible focus; do not introduce a sharp outline.
- Construct controls from existing lower-tier tokens and recipes. Do not introduce local styling values or duplicate tokens to implement these rules.
- A catalog or prototype change does not establish production behavior or tier signoff. Verify the changed artifact, report remaining gaps, and keep the live commit and CI checks enabled.
